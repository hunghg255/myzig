# Native UI additions, 2026-10-22

Compared upstream mygo `976f17c9391fb86f9afeba7a2d3b27b54e6d671a`
with myzig's `9c05b11` port baseline and the workspace's existing loading
gallery. Added:

- A separate `plugins/loading` package and public stateful `Indicator` API
  for all 29 designs. Includes duration, Blocks sweep, Ripple direction,
  Wave origin, pause/resume, reduced motion and accessible progress labels.
- Native UI scroll/pinch handlers with bubbling, clipping, transformed
  local coordinates and `Tester.pinch`; macOS, GTK, Win32 and web adapters.
- Hidden system window controls and a maximize marker whose laid-out
  rectangle reaches the existing Windows Snap Layouts backend.
- A gesture example and an end-to-end WebAssembly pinch/pan check in Node.
- English/Vietnamese docs, sidebar entries and third-party notices.

## Validation

`zig build test lines web test-web test-pages -j1 --summary all` passed:
45/45 build steps, 762 passing tests, 24 platform/availability skips.
This includes seven loading package tests and five gallery tests. All
three web examples passed Node checks; hello, pages and embed-webview
passed their real hidden-webview checks. No window was shown or system
input synthesized. Node syntax checks for the host and web test passed.

The docs site passed `npm run build`, including dead-link checking, for
both locales. VitePress's existing large-chunk warning remains.

Linux ReleaseSmall counter, hello and loading cross-compiled successfully.
The macOS counter compiled to an aarch64 object, exercising the AppKit
surface callbacks without linking against an SDK. Linux runtime tests
could not run: Docker's Linux daemon was unavailable. macOS runtime and
visual Snap Layouts behavior were not exercised on this Windows host;
the Snap rectangle lifecycle was tested in process without a native window.

An additional object-only probe that calls all three new public APIs
(loading, `handleInput`, `maximizeButton`) compiled for aarch64-macOS and
wasm32-wasi, including the marker's no-op path on both targets.

## Additional regression coverage

A follow-up audit added checks for:

- Win32 signed wheel deltas, Ctrl/Shift, ordinary notches versus pinch,
  and horizontal scrolling. `WM_MOUSEHWHEEL` now reaches handlers as `dx`.
  A real hidden window's surface adapter is called directly to verify the
  route and pointer coordinates; no OS input messages are sent or posted.
- Real DOM `WheelEvent`s in Edge headless, through `host.js`: pixel/line/
  page delta conversion, zoom direction, Ctrl-line scrolling and leaving
  browser defaults alone outside handlers. Enable this in `test-web` with
  `-Dweb-browser="/path/to/chrome-or-edge"`.
- Loading duration checked by comparing rendered phases; independent
  instance clocks and no extra elapsed time on repeated builds of a frame.
- The first valid Snap marker, movement, opacity, rotation, clipping and
  preserving manually managed rectangles when custom controls are off.

The loading target passed 14/14 tests (9 plugin, 5 gallery), the targeted
Windows adapter regression passed, and the real DOM browser check passed.

The final follow-up run of `zig build test lines test-web
-Dweb-browser="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
-j1 --summary all` passed 35/35 steps: 767 passing tests and 24 skips,
three Node/WASM scenarios and the real DOM Edge scenario. The English/
Vietnamese docs build, Zig formatting and whitespace checks also passed.

After the horizontal-wheel fix, ReleaseSmall counter grew another 512
bytes (1,149,440 to 1,149,952); hello stayed at 1,257,984 bytes. The table
above includes this follow-up in its final sizes.
